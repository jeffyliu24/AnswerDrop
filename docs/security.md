# Security model

AnswerDrop publishes documents to anyone holding a random link. It is not an encrypted vault. The server operator can read Markdown and localized images in SQLite. Use TLS and restrict filesystem access to the data directory.

## Threats and controls

| Threat                      | v0.1 control and limit                                                                                                                                                                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Markdown XSS / raw HTML     | Raw HTML is escaped. The renderer checks URL schemes and emits a small allowlisted set of tags. Reader pages use a restrictive CSP. Tests include script, event-handler, and `javascript:` cases.                                                                                                                                    |
| Malicious SVG               | Remote SVG and `data:` images are rejected. Localized images accept only PNG, JPEG, GIF, and WebP after signature checks.                                                                                                                                                                                                            |
| SSRF                        | Image fetches accept only HTTP(S), public DNS results, and ports 80/443. The resolved address is pinned for the connection. Redirects are rejected. The downloader checks every IP family and blocks loopback, private, link-local, multicast, and reserved ranges. Deployment firewalls should also block metadata/internal egress. |
| Oversized documents/uploads | API bodies and Markdown have byte limits. Images have a per-image byte cap, count cap, total cap, timeout, and content-type/signature checks. No archive decompression is performed. Animated/complex image decoders still run in the reader browser.                                                                                |
| Link guessing               | Slugs use cryptographic randomness. A slug is a bearer capability, so anyone with it can forward it. HTTP access logs can expose URLs.                                                                                                                                                                                               |
| Expiry/view limits          | SQLite atomically claims a view when the page or HTML export is requested. Images do not consume additional views. A recipient who saved the content keeps a copy after expiry.                                                                                                                                                      |
| Accidental secrets          | Modular rules flag likely secrets and local identifiers before publication. Findings require review/acknowledgement; redaction is never silent. Rules can miss secrets or report false positives.                                                                                                                                    |
| Unsafe external links       | Only HTTP(S), mailto, and safe relative/fragment links render as anchors. External links use `noopener noreferrer`; readers choose whether to follow them.                                                                                                                                                                           |
| Database boundaries         | Publisher token is separate from reader slug. There is no list endpoint. SQLite uses parameterized statements and a dedicated data directory. Back up and protect that directory.                                                                                                                                                    |
| Abuse/rate limiting         | A small in-memory per-IP limit protects preview/publish operations. It is not a distributed defense. Put a rate-limiting reverse proxy in front of a public deployment. Do not trust client-provided IP headers by default.                                                                                                          |
| Browser token exposure      | The UI keeps the publisher token in session storage. A compromised browser or same-origin script could still access it; keep the app origin dedicated.                                                                                                                                                                               |

## Operational notes

By default Docker publishes only to `127.0.0.1:3000`. Exposing it publicly requires a reverse proxy with HTTPS. Keep the publisher token out of URLs and logs. `ANSWERDROP_PUBLISH_TOKEN` can be injected from a secret manager. Rotate it if disclosed. Backups contain plaintext content.

Remote localization is optional. If it fails or is disabled, the page shows a placeholder and an external link instead of silently loading the image. The URL may still identify a private service; review findings and the Markdown before sharing.
